# v2.1.1

## Bugfix: device clock on flex/flat units was set wrong (#19)

The flex/flat time sync wrote a raw **UTC** epoch to register 40111, but the
firmware interprets that register as **local** time. The device clock therefore
ran behind by the timezone offset — 2 hours in summer, 1 hour in winter for
Europe/Berlin — on every Home Assistant start and again every 24 h.

The fix uses the Home Assistant timezone (`dt_util.now()`) and adds the current
UTC offset, exactly as the touch path already did. DST is handled automatically.

The analytics timestamp deliberately stays UTC — only the register write to the
device was affected.

Thanks to **@wfdbcw4wdn-ops** for the precise report, including the register
offset and root-cause analysis.

4 new regression tests (summer/winter offset). 774/774 tests passing.
