# v2.1.0

> ## ⚠️ Breaking change — read before updating
>
> **Entity states have changed.** Automations, scripts and templates that
> reference the old German state values **will stop working** and need updating.
> After the update, Home Assistant shows a repair notice with the full mapping.

## What changed

Home Assistant requires translation keys for entity states to be slugs
(`[a-z0-9-_]+`). This integration used German display text as the state itself
("Manuell offen", "Stufe 4 - Intensivlueftung"). That was rejected by Home
Assistant's own validation (hassfest), and it also made proper English
localisation impossible.

**What you see in the UI is unchanged** — and for English users the options are
now genuinely translated for the first time. Only the underlying state values
change:

| Entity | Old | New |
|---|---|---|
| `fan` preset_mode | `Stufe 1 - Feuchteschutz` … `Stufe 4 - Intensivlueftung` | `level_1` … `level_4` |
| Bypass control | `Manuell offen` / `Manuell zu` / `Automatisch` | `manual_open` / `manual_closed` / `automatic` |
| Operating mode | `Manuell` / `Bedarfsgesteuert` / `Wochenprogramm` / `Urlaub` / `Sommer` / `Nacht` / `Kaminbetrieb` | `manual` / `demand` / `weekly_schedule` / `away` / `summer` / `night` / `fireplace` |
| Building type | `Eigenheim` / `Mietwohnung` | `single_family` / `apartment` |
| Preheater | `Aktiv` / `Passiv` | `active` / `passive` |
| Safety manager | `Mit` / `Ohne` | `enabled` / `disabled` |

### Example

```yaml
# before
- service: fan.set_preset_mode
  target: {entity_id: fan.profi_air_400_fan}
  data: {preset_mode: "Stufe 4 - Intensivlueftung"}

# after
- service: fan.set_preset_mode
  target: {entity_id: fan.profi_air_400_fan}
  data: {preset_mode: "level_4"}
```

## Not affected

- The **"current mode" sensor** still shows German text — it has no state
  translations and was deliberately left alone, to avoid widening the breaking
  change further than necessary.
- The **device protocol is untouched**: POST values, Modbus bitmasks and the
  device's own status strings are all unchanged. This is purely a Home
  Assistant-facing change.

## Also in this release

- **English localisation of the select options** — only possible now that the
  states are slugs.
- **Repair notice after updating**, carrying the full mapping table, so nobody
  misses the change.
- **Guard tests replicating the hassfest rule**, so a regression can't slip
  through again — plus a test ensuring the device payloads didn't shift during
  the migration.
